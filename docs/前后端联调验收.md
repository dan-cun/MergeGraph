# 前后端联调验收

> 目标版本：MergeGraph 本地项目工作区 MVP
> 计划基线：2026-10-05
> 当前状态：核心联调已完成；保留的局部前端缺口在第 6 节列出。

## 1. 计划

### 目标

验证前端工作区界面是否能够调用现有后端能力，并覆盖总计划中的工作区、白板、五类图谱、节点检查器、AI 任务、AGENTS.md、文件变化和网址域名功能。

### 范围

本轮包含：

- 工作区创建、切换、刷新、关闭和重新打开。
- 工作区扫描、文件列表、文件预览和外部变化事件。
- 五类图谱加载、生成、节点选择、布局保存和失败状态。
- 节点详情、任务关联、证据和最近修改。
- AI 任务提交、步骤事件、停止、补丁、检查、回滚和主流程更新。
- AGENTS.md 发现、刷新、按文件路径获取有效规则。
- 网址与域名扫描、列表、编辑和删除。
- Provider 全项目设置。
- 空态、错误态、加载态和重复点击处理。

本轮不包含：

- MCP、ComfyUI、Seedance 实际调用。
- 多用户协作、远程项目、在线部署执行。
- 安全测试、渗透测试和生产凭据审计；只验证功能路径和必要的错误显示。

### 依赖

- Node.js 22 或更高版本。
- 本地项目目录可读写。
- npm start 启动 MergeGraph 服务，默认地址 http://127.0.0.1:4310/。
- 浏览器启用 JavaScript。
- 测试项目至少包含一个可读取的源文件，若要验证 AGENTS.md、网址或域名，需要准备对应文件。
- API Key 为可选；没有外部 Provider 时使用已标注的本地 mock 模式。

### 风险与回退

| 风险 | 影响 | 回退 |
|---|---|---|
| 大目录首次扫描耗时 | 用户误认为按钮无响应 | 显示提交状态；必要时先返回 queued，再异步生成图谱 |
| 图谱生成失败 | 当前图谱不可见 | 保留并展示 last good 版本，标记 stale |
| SSE 断开或事件延迟 | 步骤状态不同步 | 使用任务详情和步骤接口轮询补偿 |
| 外部文件频繁变化 | 重复扫描和重复事件 | 防抖、哈希去重、记录来源 |
| AGENTS.md 规则冲突 | AI 任务使用错误指令 | 按目录深度排序并显示实际生效文件 |
| Provider 不可用 | AI 任务无法规划 | 显示错误和本地 mock 状态，不伪造成功 |
| 接口返回字段变化 | 前端空白或错误 | 统一响应适配、记录原始错误、保留最近可用状态 |

## 2. 验收矩阵

状态定义：通过 = 结果和证据满足要求；有条件通过 = 主链路可用但存在已记录限制；不通过 = 失败或缺少关键能力；待核实 = 尚未完成本轮验证，不能推断为通过。

| 编号 | 场景 | 前端动作 | 后端接口/证据 | 验收标准 | 状态 |
|---|---|---|---|---|---|
| WS-01 | 首次打开 | 访问根地址 | GET /api/health、GET /api/workspaces | 页面无 JS 错误，显示空态或最近工作区 | 待核实 |
| WS-02 | 创建工作区 | 填写目录并点击“打开工作区” | POST /api/workspaces | 立即显示加载状态；成功后弹窗关闭、路径和名称正确 | 待核实 |
| WS-03 | 扫描刷新 | 点击刷新工作区 | POST /api/workspaces/:id/scan | 文件统计更新，扫描错误可见 | 待核实 |
| WS-04 | 切换工作区 | 选择最近工作区 | GET /api/workspaces/:id 或等价加载 | 图谱、任务、指令和部署数据属于当前工作区 | 待核实 |
| WS-05 | 关闭/重开 | 关闭后重新打开 | POST .../:id/close、GET .../:id | 状态可恢复，watcher 不重复创建 | 待核实 |
| FILE-01 | 文件列表 | 打开文件扫描 | GET /api/workspaces/:id/files | 展示路径、大小、哈希或修改状态 | 待核实 |
| FILE-02 | 文件预览 | 点击文件或节点 | GET /api/workspaces/:id/file?path=... | 显示内容或可理解错误 | 待核实 |
| FILE-03 | 外部变化 | 在外部编辑文件 | GET /api/workspaces/:id/events | 事件带路径、来源和状态，节点可高亮 | 待核实 |
| GRAPH-01 | 五类页签 | 依次切换五类图谱 | GET /api/graphs | 每类独立显示状态、节点、边和错误 | 待核实 |
| GRAPH-02 | 生成 | 点击“生成图谱” | POST /api/graphs | 显示生成中，成功后更新版本和白板 | 待核实 |
| GRAPH-03 | 布局 | 拖动节点、缩放平移 | PUT/PATCH /api/graphs/:id[/layout] | 刷新后节点位置保持，边仍连接正确节点 | 待核实 |
| GRAPH-04 | 节点检查器 | 点击节点 | GET /api/graphs/:id/nodes/:nodeId | 显示作用、路径、边、证据、任务和最近变更 | 待核实 |
| GRAPH-05 | 失败回退 | 模拟图谱失败或读取失败 | 图谱状态、last good 记录 | 不覆盖最近可用版本，显示 stale/失败原因 | 待核实 |
| TASK-01 | 提交任务 | 在底部输入框发送任务 | POST /api/tasks | 快速返回任务 ID 和 queued/planning 状态 | 待核实 |
| TASK-02 | 实时步骤 | 观察任务控制台 | GET /api/tasks/:id/events、steps | 能看到计划、当前步骤、文件和检查状态 | 待核实 |
| TASK-03 | 文件修改 | 提交可执行任务 | patches、workspace files | 修改路径、补丁和哈希可追溯 | 待核实 |
| TASK-04 | 停止 | 执行中点击停止 | POST /api/tasks/:id/cancel | 任务停止，已完成步骤保留 | 待核实 |
| TASK-05 | 回滚 | 失败任务点击回滚 | POST /api/tasks/:id/rollback | 文件恢复，产生回滚事件和状态 | 待核实 |
| TASK-06 | 任务历史 | 打开任务面板 | GET /api/workspaces/:id/tasks | 能查看历史任务和状态 | 待核实 |
| INST-01 | 发现指令 | 打开项目指令 | GET /api/instructions | 显示每个 AGENTS.md 路径、哈希和作用域 | 待核实 |
| INST-02 | 刷新指令 | 点击刷新 | POST .../:id/instructions/refresh | 新增/修改/删除规则可见 | 待核实 |
| INST-03 | 有效规则 | 选中文件或任务 | GET .../instructions/effective?path=... | 显示实际生效的规则文件和优先级 | 待核实 |
| DEP-01 | 发现资源 | 点击网址与域名扫描 | POST /api/deployments/discover | 配置文件中的 URL/域名出现 | 待核实 |
| DEP-02 | 编辑资源 | 新增、修改、删除资源 | deployment POST/PATCH/DELETE | 列表和部署图同步 | 待核实 |
| PROVIDER-01 | Provider | 打开设置并保存 | GET/PUT /api/settings/provider | 保存成功提示，密钥不回显 | 待核实 |
| UI-01 | 空态与错误态 | 空目录、失败接口、无规则 | 各接口错误响应 | 文案准确，操作可重试，不把空态当成功 | 待核实 |
| UI-02 | 重复操作 | 连续点击创建、生成、发送 | 请求记录 | 按钮在请求中禁用或请求可安全去重 | 待核实 |

## 4. 结果记录规则

每个验收项更新为：

- 通过：有浏览器操作和 API 响应证据。
- 有条件通过：主链路可用，但保留明确的性能或展示限制。
- 不通过：功能不可用、数据串工作区或出现无法恢复的错误。
- 待核实：尚未完成验证，不能推断为通过。

记录问题时写明：复现步骤、实际结果、预期结果、请求或日志证据、影响范围和下一步责任模块。不得把“尚未生成”“尚未发现”“本地模式”等正常状态写成缺陷。

## 5. 当前基线结论

静态盘点显示，前端已有工作区表单、图谱页签、SVG 白板、节点检查器、任务输入、Provider 设置和基础事件订阅；后端已有工作区、扫描、图谱、任务、指令、部署和 Provider 路由。

基线仍有四类需要联调确认的问题：

1. 创建工作区请求同步等待扫描和五类图谱生成，慢目录时缺少加载反馈。
2. 前端没有接入文件列表/预览、工作区事件、AGENTS 有效规则、部署编辑发现和任务历史等接口。
3. 任务 POST 返回前会等待执行，前端随后才启动 SSE，实时步骤显示需要重新验证。
4. 非主流程图的节点语义、失败回退和证据展示需要以实际响应确认。

本文件只记录计划和验收证据，不把尚未运行的场景标为通过。主 agent 完成本轮修复后，应更新矩阵状态并补充实际证据。
