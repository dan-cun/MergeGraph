# MergeGraph 总体实施任务

## 1. 本次版本目标

把 MergeGraph 改造成一个面向本地项目的 AI 编程工作区：用户选择一个项目目录后，在白板上查看项目图谱，在底部对话框直接发起编码任务，AI 按步骤修改工作区文件，并把每一步涉及的文件、任务和图谱变化同步到界面。

本次实施采用直接改造方式。现有代码中不适合目标交互的画布、流程图状态和运行入口可以删除重写；文件扫描、路径安全、快照、证据链和 Provider 基础能力优先复用。MCP、ComfyUI、Seedance、团队协作权限只预留扩展接口，不进入本次验收范围。

## 2. 目标边界

### 本次必须完成

- 本地项目目录选择和工作区切换。
- 白色白板背景、顶部五类图谱页签、右侧检查面板、底部 AI 编程对话框。
- 主体流程图、调用资产图、执行逻辑图、Agent 关系图、网址与域名图。
- AI 任务拆解、步骤状态、文件补丁、代码写入、检查和回滚记录。
- 被修改文件在主流程图中高亮。
- 点击节点后查看文件或目录作用、当前任务、证据和最近修改。
- 分层 `AGENTS.md` 发现、继承和任务注入。
- Archify 的结构化 JSON、校验、渲染和生成回执接入。

### 本次暂缓

- MCP 工具市场和远程 MCP 服务。
- ComfyUI、Seedance 的实际调用。
- 多用户、团队权限和远程协作。
- 云端项目同步和在线部署执行。

## 3. 总体架构

```text
Vue 工作区
├── WorkspaceShell
│   ├── ProjectPicker
│   ├── GraphTabs
│   ├── Whiteboard
│   ├── InspectorDrawer
│   └── AiTaskConsole
├── 状态层
│   ├── workspaceStore
│   ├── graphStore
│   ├── taskStore
│   └── instructionStore
└── 事件订阅
    └── task/file/graph 事件流

Node 本地服务
├── workspace service       工作区、路径和扫描
├── graph service           五类图谱和版本
├── task executor           AI 任务、补丁和步骤
├── instruction service     AGENTS.md 解析和作用域
├── change tracker          快照差异、Git 差异和文件事件
├── deployment service      URL、域名和服务关系
└── archify bridge          JSON、校验、渲染和回执

SQLite
├── projects / project_files / snapshots
├── graph_documents / graph_nodes / graph_edges
├── conversations / tasks / task_steps
├── file_change_events / patches / checks
├── project_instructions
└── deployment_resources
```

本次不把“项目隔离”作为单独冻结阶段。当前运行时以 `workspace_id` 作为工作区索引，图谱另外携带 `graph_type`；数据层保持可调整，后续再根据真实使用情况收敛正式数据契约。

### 破坏性改造清单

以下旧链路不做兼容迁移，开发阶段允许清空本地 `data/` 后重新初始化：

- 删除全局 `canvas_nodes`、`canvas_edges`，替换为项目作用域的 `graph_documents`、`graph_nodes`、`graph_edges`。
- 删除只支持 architecture 的旧分析主链路，改为统一的 typed `GraphIR` 生成任务。
- 删除将资产上下文运行误作代码任务的 `/api/runs` 主入口，改为 `/api/tasks`、`/api/tasks/:id/steps`、`/api/tasks/:id/patches` 和事件流。
- `server.mjs` 只保留启动和路由注册，扫描、任务、图谱、指令和 Archify 逻辑拆到 `lib/` 模块。
- 旧前端画布布局、硬编码连线和假图类型切换可以直接删除重写。

## 4. 前端任务

### F1. 重写工作区壳层

**实现方法**

- 保留 Vue，按组件拆分现有单文件模板。
- 将现有顶栏和页面条件渲染改为 `WorkspaceShell`。
- 左侧只保留项目、扫描、任务、设置等导航；图谱类型放到顶部页签。
- 中央区域固定为白板，底部固定 AI 对话框，右侧使用可收起抽屉。
- 工作区未选择时显示目录选择和最近项目入口。

**验收结果**

- 界面结构与设计稿一致：顶部页签、中央白板、右侧信息区、底部对话区均存在。
- 切换项目或页签时，对话内容和当前任务不会错误串接。
- 右侧抽屉可以打开、关闭、固定和跟随选中节点。

### F2. 重写白板渲染器

**实现方法**

- 第一版使用 SVG 实现节点、边、选中和高亮，保留后续替换为 Canvas/WebGL 的可能。
- 节点位置保存到后端，不再按数组索引计算。
- 边使用 `source` 和 `target` 节点 ID计算，禁止硬编码坐标。
- 提供缩放、平移、适配视图、节点聚焦和拖拽。
- 节点绑定 `file_path`、`directory_path`、`task_id` 和 `evidence_ids`。

**验收结果**

- 刷新页面后节点位置、大小和折叠状态保持。
- 点击节点能定位到对应文件或目录。
- 只高亮当前任务涉及的节点，其他节点保持普通状态。
- 图谱边不会因为节点拖动而断开。

### F3. 实现五类图谱页签

| 页签 | 前端状态 | 首次生成 | 增量更新 |
|---|---|---|---|
| 主体流程图 | `main_flow` | 工作区扫描后生成骨架 | 每个 AI 步骤完成后更新 |
| 调用资产图 | `asset_call` | 扫描已知资源 | 根据导入、调用和依赖事件更新 |
| 执行逻辑图 | `execution` | 打开项目后优先生成 | 重新分析代码结构 |
| Agent 关系图 | `agent_relation` | 读取 AGENTS、Skill、MCP 声明 | 根据任务和规则引用更新 |
| 网址与域名 | `deployment_ownership` | 默认空图 | 读取配置和用户输入更新 |

**验收结果**

- 五个页签都能显示独立图谱或明确的空状态。
- 页签之间不会共用错误的节点和边。
- 图谱生成失败时，界面显示失败原因和上一次可用版本。

### F4. 实现底部 AI 编程对话框

**实现方法**

- 对话消息分为用户请求、AI 计划、工具调用、文件变更、检查结果和最终摘要。
- 发送消息后创建 `task`，任务下生成多个 `task_step`。
- 通过 SSE 或短轮询接收步骤进度。
- 支持查看补丁、重新执行失败步骤、停止当前任务和回滚任务。
- 高风险操作保留一次确认入口。

**验收结果**

- 用户输入一句修改要求后，界面显示任务计划和当前步骤。
- 每个步骤显示状态、涉及文件、执行时间和检查结果。
- AI 完成后能列出修改文件、测试结果和图谱更新结果。

### F5. 实现右侧节点检查器

**实现方法**

- 节点点击后请求节点详情 API。
- 显示文件路径、目录作用、证据来源、依赖关系、最近任务和当前步骤。
- 对正在修改的文件显示“正在完成的任务”。
- 对推断信息标记证据状态：`confirmed`、`inferred`、`unknown`。

**验收结果**

- 点击文件节点可以看到文件作用和当前任务。
- 点击目录节点可以看到目录下的文件摘要和依赖。
- 没有证据的描述不会被显示为确定事实。

## 5. 后端任务

### B1. 工作区和文件扫描

**实现方法**

- 复用当前路径规范化、项目根目录校验和只读扫描。
- 增加 `workspace_id` 和项目当前状态。
- 支持创建、打开、刷新和关闭工作区。
- 统一生成文件清单、快照和文件内容摘要。

**验收结果**

- 用户选择目录后能创建工作区并完成首次扫描。
- 工作区外路径不能被任务写入。
- 重新打开工作区能恢复最近图谱、任务和对话摘要。

### B2. 图谱服务

**实现方法**

- 删除现有全局画布替换逻辑，新增项目作用域的图谱 CRUD API。
- 统一图谱结构：`graph_type`、`version`、`nodes`、`edges`、`evidence`、`status`。
- 每种图谱由独立适配器生成，不在路由中写死 architecture。
- 保存 `last_good`、`stale`、`failed` 和失败原因。

**验收结果**

- 五类图谱可独立创建、读取、更新和回退。
- 节点、边、文件和任务之间可以互相跳转。
- 生成失败不会覆盖上一次可用图谱。

### B3. AI 编程任务执行器

**实现方法**

当前实现先以一个可运行服务聚合以下职责，后续可按规模拆分为独立模块：

```text
lib/task-service.mjs
lib/change-tracker.mjs
lib/core.mjs
```

执行顺序：

```text
创建任务
→ 读取有效 AGENTS.md
→ 读取项目快照和相关文件
→ 生成步骤计划
→ 生成补丁
→ 校验补丁路径
→ 应用补丁
→ 运行检查
→ 记录文件变化
→ 更新图谱
→ 输出任务总结
```

AI 输出限定为结构化文件操作或 unified diff，不接受未经校验的自由 shell 字符串。写入前保存任务级备份；验证命令使用白名单；写入后记录 stdout、stderr 和退出码。

补丁应用必须记录：

- 修改前哈希。
- 修改后哈希。
- 修改文件列表。
- 补丁正文或补丁存储位置。
- 检查命令和退出码。
- 失败原因和回滚点。

**验收结果**

- AI 可以完成一个小型代码修改任务。
- 修改范围超过工作区时任务失败且不写入文件。
- 检查失败时可以回滚到任务前状态。
- 每一步都能向前端推送状态事件。

### B4. 文件变化追踪

**实现方法**

- 首选任务执行器产生的文件变化事件。
- 增加快照前后 diff，作为补充校验。
- 接入 `fs.watch` 和防抖，监听结果使用哈希复核，并区分 `ai`、`external`、`scan` 来源。
- 第一版不依赖文件监听推断任务，任务执行器事件是任务上下文的主要来源。
- 为每个变化保存 `task_id`、`step_id`、路径、操作类型和哈希。

**验收结果**

- 每次 AI 修改都能得到新增、修改、删除文件列表。
- 主流程图可以根据文件变化高亮节点。
- 文件变化与任务步骤能够追溯对应。

### B5. AGENTS.md 指令服务

**实现方法**

- 从工作区根目录递归发现 `AGENTS.md`。
- 按目录深度计算作用范围。
- 目标文件同时命中多份规则时，子目录规则优先。
- 保存路径、哈希、作用范围、解析结果和有效规则文本。
- 在 AI 任务详情中显示使用过的规则文件。

**验收结果**

- 根目录规则可以影响整个项目。
- 子目录规则只影响对应目录。
- AI 能说明某次修改受到哪几份 `AGENTS.md` 约束。
- 规则变更后，下一次任务自动使用新内容。

### B6. Archify 桥接

**实现方法**

- MergeGraph 负责扫描、任务、事件、图谱绑定和证据。
- Archify 负责类型化 JSON 校验、渲染、HTML/SVG 交付和检查。
- 固定 Archify 版本并保存生成命令、输入 JSON 哈希、输出文件和检查结果。
- 当前 `lib/architecture-ir.mjs` 保留为兼容层，逐步增加 workflow、sequence、dataflow、lifecycle 适配器。

**验收结果**

- 每个图谱类型都能生成符合 schema 的输入。
- 生成成功后有可打开的 HTML/SVG 或明确的错误回执。
- Archify 失败时保留 MergeGraph 上一次可用版本。

### B7. 网址与域名服务

**实现方法**

新增 `deployment_resources`：

```text
id
workspace_id
url
domain
environment
provider
service_node_id
related_files
verification_status
source
updated_at
```

- 读取 `.env.example`、部署配置、反向代理配置、Docker 配置和前端 API 配置。
- 用户可以手动新增、修改和删除网址或域名。
- 将 URL、域名、服务节点和部署文件连成图谱。
- 自动推断的关系必须标记来源和可信度。

**验收结果**

- 能显示项目中的 URL 和域名。
- 能把域名关联到前端、API 或部署服务。
- 配置文件和用户手动输入可以区分。
- 无法验证的域名显示“待核实”。

## 7. 实施顺序

### 第一批：可用工作区

- 重写前端工作区壳层。
- 重写白板组件。
- 重写图谱状态。
- 增加项目作用域图谱 API。
- 完成五类页签和节点详情。

### 第二批：可执行 AI 编程

- 增加对话、任务和步骤模型。
- 增加补丁应用和检查。
- 增加文件变化事件。
- 完成主流程图文件高亮。

### 第三批：规则和增量图谱

- 完成 `AGENTS.md` 作用域解析。
- 完成其他四类图谱增量更新。
- 完成网址与域名图谱。
- 接入 Archify 生成回执。

### 第四批：质量收尾

- 回滚、失败恢复和 last-good。
- API 密钥系统凭据存储。
- 启动流程、错误提示和文档。
- 为后续 MCP、ComfyUI、Seedance 保留 provider 接口。

### 粗略排期

按当前代码规模、单人开发和本地 Provider 可用估计：

| 批次 | 预计时间 | 主要可交付物 |
|---|---:|---|
| 第一批 | 2–4 个工作日 | 工作区壳层、白板、五类页签、图谱 API |
| 第二批 | 3–5 个工作日 | 对话、任务、步骤、补丁、文件事件和高亮 |
| 第三批 | 3–5 个工作日 | AGENTS.md、增量图谱、网址域名、Archify 回执 |
| 第四批 | 2–4 个工作日 | 回滚、失败恢复、密钥存储、文档和回归验证 |

完整核心闭环粗估为 10–18 个工作日；Archify renderer 适配难度、AI Provider 输出稳定性和本地任务验证命令会影响实际时间。外部连接器和协作权限不计入本排期。

## 8. 总体验收结果

全部完成后，应满足以下场景：

1. 用户选择一个本地目录，创建工作区。
2. 系统自动生成执行逻辑图和主体流程图骨架。
3. 用户在底部输入“增加一个登录接口”。
4. AI 读取适用的 `AGENTS.md`，拆分任务并显示步骤。
5. AI 修改文件、运行检查并记录补丁。
6. 被修改文件在主体流程图中高亮。
7. 点击节点，右侧显示文件作用、当前任务和修改证据。
8. 调用资产图、Agent 关系图和网址域名图逐步补充。
9. Archify 输出可打开的图谱结果。
10. 任务失败时可以查看原因并回滚。
