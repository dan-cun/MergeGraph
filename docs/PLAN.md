# MergeGraph 首轮执行计划

## 目标

在本地完成五个参考仓库的代码理解与解释文档，并搭建 MergeGraph 首轮可运行原型。首轮聚焦无限画布、工具节点、资产管理、版本/谱系与旁车上下文格式，使用第三方 API 贯通最小链路，暂不实现 Agent 网络、ComfyUI 适配器和 Seedance 适配器。

## 工作流

1. 并行克隆并分析参考仓库，记录 commit、许可证、依赖、运行方式、核心数据结构、前后端边界和可复用实现。
2. 汇总五个仓库的架构差异，确定 MergeGraph 的数据模型、存储模型、画布模型、工具接口和旁车文件格式。
3. 配置本地开发环境，统一把项目工具、缓存和构建产物放到 `D:/APP/MergeGraph`，避免污染系统目录。
4. 搭建主项目基础结构，先实现文件导入、资产登记、旁车生成、搜索、画布节点/边、工具执行和第三方 API 调用。
5. 每个设计阶段完成后由独立审查代理检查：需求覆盖、数据可迁移性、错误恢复、许可证引用、可复现启动和运行链路。
6. 运行端到端验收：导入资产 → 提取元数据 → 生成旁车 → 进入画布 → 调用第三方 API → 保存结果 → 建立谱系 → 可检索和导出。

## 阶段

### P0 资料与环境

- 五个仓库克隆到 `repos/`。
- 为每个仓库生成解释文档。
- 生成架构对比和许可证清单。
- 创建 `D:/APP/MergeGraph` 工具、缓存和构建目录。

**状态：完成。**

### P1 数据和文件格式

- 定义 Asset、Artifact、ContextSidecar、Canvas、ToolRun、Lineage、LicenseRecord。
- 定义 JSON Schema 和 SQLite 表结构。
- 实现旁车读写、内容哈希和版本号。

**状态：完成。** 首轮 JSON sidecar 和 SQLite schema 已运行，并通过 P3 数据一致性复验。

### P2 首轮应用框架

- 前端：无限画布、节点/边、资产卡片、详情面板、搜索。
- 后端：导入、元数据提取、缩略图、旁车、SQLite、全文检索、第三方 API 代理。
- 工具：导入目录、分析资产、生成上下文、调用 API、保存结果。

**状态：完成首轮闭环。** 当前预览使用浏览器原图裁剪，独立缩略图队列留作下一轮性能优化。

### P3 端到端链路

- 使用一个第三方文本/图像 API 完成一次生成。
- 保存请求、输入资产、模型参数、结果和错误。
- 在画布中显示输入、执行和结果的谱系。

**状态：完成。** 当前已接通通用 OpenAI-compatible 文本接口和本地 mock；Seedance/ComfyUI 适配仍按计划后置。

### P4 审查与迭代

- 独立审查代理逐项检查。
- 修复阻断问题。
- 补充启动文档、引用仓库、许可证和迁移说明。

**状态：完成首轮。** P1、P2、P3 审查报告均已落在 `research/reviews/`。

## 验收标准

- 全部五个仓库存在本地并有对应分析文档。
- MergeGraph 可以从空目录启动。
- 资产导入后有稳定 ID、内容哈希、可预览内容和旁车文件；独立缩略图队列列入下一轮。
- 画布可以创建节点、连线、保存和重新打开。
- 工具调用第三方 API 后，结果、参数、输入和错误可追溯。
- 资产可按文本、标签、类型和时间检索。
- 旁车格式独立于 UI，能在命令行中读写并通过 JSON Schema 校验。
- 关键参考仓库、许可证和借鉴点在项目文档中明确声明。
