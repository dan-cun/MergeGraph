## 5. 基线中的前端展示缺口

1. taskHistory 在 applyTask 中维护，但模板没有渲染任务历史。
2. “文件扫描”侧栏只展示文件计数和根目录，没有文件列表、内容预览和变化来源。
3. “项目指令”侧栏只展示 AGENTS.md 数量，没有规则文件列表、有效作用域和刷新入口。
4. “网址与域名”侧栏只展示资源数量，没有扫描、编辑、删除或验证入口。
5. 节点检查器展示基础路径和证据字符串，没有完整显示关联边、最近变更、任务步骤、证据等级和检查结果。
6. 任务控制台有停止和回滚入口，没有单步重试、补丁详情、检查详情和任务历史入口。
7. 图谱页签支持生成当前图谱，但没有历史版本恢复、预览和上一份可用版本操作。
8. 白板支持节点拖动、缩放、平移和布局保存；基线模板没有折叠节点控制和保存 viewport 的独立操作。
9. public/app.js 是单文件内联 Vue 模板，尚未拆分为总体计划中的组件和状态模块。

## 6. “打开工作区”基线问题

createWorkspace 会等待 POST /api/workspaces 完成；服务端该请求还会执行 watcher 启动、完整扫描和五类图谱生成后才返回。因此大目录或图谱生成较慢时，按钮看起来没有反应。基线前端没有提交中状态、进度文案或按钮禁用状态，错误只通过全局提示显示。

修复后的验收要求：

- 点击后立即出现“正在扫描/生成图谱”状态，按钮不可重复提交。
- 成功后关闭工作区弹窗并显示项目名称、路径和图谱状态。
- 失败时在弹窗附近显示可理解的错误，并允许重试。
- 创建期间刷新页面不会产生重复工作区记录。

## 8. 2026-10-05 修复后结果

### 已接通并验证

- 工作区创建接口改为快速返回，后台执行扫描和五类图谱生成；前端按钮显示“正在扫描并生成图谱…”，创建期间禁止重复提交。
- 新增工作区初始化状态查询：`GET /api/workspaces/:id/status`；前端通过轮询和工作区 SSE 更新图谱与文件状态。
- 文件索引已连接 `GET /api/workspaces/:id/files`，前端显示路径、语言和大小。
- 工作区关闭、文件事件、图谱恢复、任务历史、任务详情、网址与域名发现已有前端入口或调用函数。
- 任务创建改为后台执行，前端可以先建立任务流；补丁接口返回真实 patch 记录。
- 文件接口响应已移除完整 `content` 字段，内容仅在用户请求单个文件预览时读取。

### 仍属于前端待补齐项

- AGENTS 有效规则按文件路径的预览界面。
- 网址与域名的手动新增、编辑、删除和验证状态操作。
- 图谱历史版本列表和 HTML/SVG 预览面板。
- 任务补丁详情、检查结果和单步重试界面。
- 节点详情中的边、最近变更、证据等级和任务步骤完整展示。
- `public/app.js` 拆分为计划中的 Vue 组件与状态模块。

### 结论

“打开工作区”无响应的根因是服务端同步执行全量扫描和五类图谱生成，原始接口实测约 22 秒。修复后工作区 POST 实测约 0.2 秒返回 201，扫描和图谱生成在后台完成。第 2 至第 5 节中的空态文案属于正常数据状态，后续功能补齐时继续保留清晰的空态与错误提示。
